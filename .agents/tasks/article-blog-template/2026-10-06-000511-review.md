# RHL Article / Blog Post Page Template

This implementation adds a reusable article/blog page template to the existing TanStack Start retail site, driven entirely from a typed data model in `src/data/blog.ts`. The approach expands the existing `BlogPost` interface with optional structured-content fields, seeds the "How to Improve Blood Circulation Naturally" article, builds 15 new components in `src/components/blog/`, and rewrites `blog.$slug.tsx` into a two-column desktop / single-column mobile layout. All 4 pre-existing blog posts continue to render via a `legacyBody` fallback path in `ArticleBody`. The build exits 0 with no TypeScript errors.

Watch for: the `categorySlug` breadcrumb link resolves to `/blog` rather than a filtered URL — the category level of the breadcrumb is non-functional (confirmed). The 4 recommended products for the circulation article use generic wholesale `supportStatement` text rather than article-specific benefit copy, because none of the 4 slugs are in the curated product set (confirmed).

**Verdict**: APPROVED


## High-level view

The two-column layout is implemented cleanly with `flex flex-col lg:flex-row` and a separate `lg:hidden` block for mobile sidebar modules. Desktop sticky sidebar (`sticky top-24`) and the mobile module order (U20X → Subscribe → Recent → Explore) both match the spec exactly. The route adds neither `<Header>` nor `<Footer>` imports — those remain solely in `__root.tsx`.

All article content including sections, products, references, disclaimer and copyright flows from `src/data/blog.ts` with no copy hardcoded in component files. The `GLOBAL_DISCLAIMER` constant is always passed to `DisclaimerAccordion`; `ArticleCopyrightNotice` injects `new Date().getFullYear()` at render time. Both behaviors are unconditional.

The `categorySlug` prop is accepted and typed in `Breadcrumbs` but silently discarded (`_categorySlug`). The category breadcrumb link resolves to `/blog` rather than a filtered listing. This is a known scope decision noted in the plan but it leaves the third breadcrumb segment non-actionable.

`RecommendedProducts.tsx` returns `null` on an empty match, so articles with no recognized product slugs render cleanly. The 4 slugs in the circulation article resolve from the merged wholesale catalog but carry generic `supportStatement` copy (`"Everyday wellness support in a vcap."`) rather than a benefit statement tuned to the article's topic.

`NewsletterSubscribe` uses `react-hook-form` + zod with a proper `<label htmlFor="subscribe-email">` association, `aria-describedby` on the input, and `role="alert" aria-live="polite"` on the error paragraph — the full a11y pattern is in place. The form simulates a successful submission unconditionally; wiring a real endpoint is a one-line swap.

`U20XPromo` applies the navy-to-blue gradient via inline `style` using `var(--u20x-navy)` and `var(--u20x-blue)` CSS variables — correct for Tailwind v4 where arbitrary CSS variable utilities aren't auto-registered. The CTA uses the same variable for text color, and trust badges are rendered.

<summary>Issues (2)</summary>

1. **Non-functional category breadcrumb** — `Breadcrumbs.tsx` accepts `categorySlug` but discards it; the category segment links to `/blog` instead of `/blog?category={slug}` or `/blog/{slug}`. A reader clicking the third breadcrumb level gets the full unfiltered listing. Fix by passing `categorySlug` to a filtered blog URL when category filtering is built, or by removing the link and rendering the category as plain text until then.

2. **Generic product benefit copy on circulation article** — the 4 recommended products (`organic-beet-root`, `full-spectrum-cayenne`, `anthocyanin-bilberry`, `adaptogen-vitality-complex`) are not in the curated product set, so they render with the wholesale template fallback (`"Everyday wellness support in a vcap."`). Add curated entries for these slugs in `catalog.ts` with circulation-specific `supportStatement` text, or add a per-article `productBenefits?: Record<string, string>` field to `BlogPost` so the article data can supply the copy.

<details>
<summary>Details</summary>

### Category breadcrumb resolves to the wrong destination

`Breadcrumbs.tsx` receives `categorySlug` in its props interface and TypeScript is satisfied, but the destructuring aliases it to `_categorySlug` and the category `<Link>` hardcodes `to="/blog"`. The category level of the breadcrumb is therefore non-navigable to the correct filtered view. Since category filtering isn't in scope for this PR (confirmed by the plan), the options are: keep it as-is and accept the limitation, or render the category as plain `<BreadcrumbPage>` text rather than a link to avoid implying navigability that doesn't exist.

### Recommended product benefit copy

`getProducts()` merges `curatedProducts` and `catalogProducts` (wholesale). The circulation article's 4 slugs are wholesale-only entries. The wholesale template assigns `supportStatement: "Everyday wellness support in a ${form}."` — for a capsule this becomes `"Everyday wellness support in a vcap."`, which is semantically correct but not persuasive or article-relevant. This isn't broken behavior (the component renders, products link correctly to `/products/$slug`), but the benefit line shown on the product cards doesn't support the article's circulation narrative. Curating those 4 slugs in `catalog.ts` or exposing a per-article override field is the cleaner fix.

</details>
